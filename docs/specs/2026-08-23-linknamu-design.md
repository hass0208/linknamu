# 링크나무 설계 문서

## 개요
- 서비스 이름: 링크나무
- 한 줄 설명: 내 모든 링크를 한 페이지에 모아 두고, 하나의 URL로 공유하는 서비스
- 범위: 본인 전용 (회원가입/로그인 없음). 여러 사용자를 지원하는 멀티유저 서비스가 아니다.

## 기술 스택
- Next.js 16 (App Router)
- TypeScript
- Tailwind CSS (모바일 우선 반응형)
- MongoDB Atlas (링크 클릭 수 집계 전용)
- Vercel 배포

## 페이지 구조
- `/` — 프로필 페이지
  - 원형 프로필 사진, 이름, 한 줄 소개, 링크 카드 목록 (와이어프레임 참고)
  - 링크 카드는 `/r/[linkId]`로 연결
- `/r/[linkId]` — 리다이렉트 라우트 핸들러
  - MongoDB `clicks` 컬렉션에서 해당 `linkId`의 count를 +1
  - 실제 대상 URL로 302 리다이렉트
  - 존재하지 않는 linkId면 `/`로 리다이렉트
  - MongoDB 연결/쓰기 실패 시에도 리다이렉트 자체는 반드시 성공해야 함 (집계 실패를 사용자 경험 실패로 이어지게 하지 않는다)
- `/stats` — 클릭 수 확인 페이지
  - 비밀번호 입력 폼 → 서버 액션에서 `.env.local`의 `STATS_PASSWORD`와 비교
  - 일치 시 httpOnly 쿠키 발급 (세션 저장소 없이 단순 플래그 쿠키)
  - 인증된 상태에서만 링크별 클릭 수 목록 표시

## 데이터
### 정적 설정 (코드 내, DB 아님)
`src/config/links.ts` 에 하드코딩:
- 프로필: 이름, 한 줄 소개, 프로필 사진 경로(public 폴더 이미지)
- 링크 목록: `{ id, label, url }[]`

### MongoDB Atlas
- 컬렉션: `clicks`
- 문서 형태: `{ linkId: string, count: number }`
- `/r/[linkId]` 요청마다 `upsert`로 `count`를 +1 (문서 없으면 생성)

## 환경 변수 (.env.local, 커밋하지 않음)
- `MONGODB_URI`
- `STATS_PASSWORD`

## 에러 처리
- 잘못된 `linkId` → `/`로 리다이렉트
- MongoDB 연결 실패 → 로그만 남기고 리다이렉트는 정상 진행
- `/stats` 비밀번호 불일치 → 에러 메시지와 함께 입력 폼 재표시

## 테스트/검증 범위
- 로컬 개발 서버에서 브라우저로 직접 확인:
  - `/` 프로필 페이지 렌더링 (모바일/데스크톱 반응형)
  - 링크 카드 클릭 → `/r/[linkId]` 경유 → 실제 URL로 이동 확인
  - MongoDB에 클릭 수가 실제로 증가하는지 확인
  - `/stats` 비밀번호 보호 및 클릭 수 표시 확인
- 별도 자동화 테스트 스위트는 MVP 범위에서 제외 (프로젝트 규모상 build-test/code-reviewer 실행 검증으로 충분)

## 스코프 제외 (Out of Scope)
- 회원가입/로그인, 멀티유저 지원
- 링크/프로필을 UI에서 편집하는 관리자 화면
- 클릭 수 외 상세 분석(리퍼러, 지역, 기기 등)
